# S²HR-v1 FIDA-v0 Reproduction Guide

FIDA-v0 is a frozen epoch-25 checkpoint audit. It decomposes the deployment-time
effects of BPS-CH and SPSR, measures their interaction, separates the joint-training
trajectory from direct innovation effects, and diagnoses deep spatial-teacher and
boundary-controller reliability.

It performs no training, optimizer construction, parameter update, checkpoint
write, hyperparameter sweep, test evaluation or LUAD evaluation.

## Repository structure

```text
tool/infer_s2hr_fida.py        # same-base TTA instrumentation and overrides
tools/s2hr_fida_metrics.py     # streaming official and diagnostic metrics
tools/audit_s2hr_fida.py       # parity, full audit, figures and report
tests/test_s2hr_fida.py        # frozen design and metric safety tests
```

The original S²HR model and checkpoint are read only. BPS OFF directly sets the
effective CH gate to one; SPSR OFF directly sets its effective residual scale to
zero. Neither override edits a parameter tensor.

## Data organization

```text
BCSS-WSSS/val/
├── img/   # exactly 3,418 validation images
└── mask/  # diagnosis/evaluation only; never enters model forward
```

Only BCSS validation is accepted. Paths containing `test` or `luad` are rejected.

## Training

There is no FIDA training command. Creating an optimizer, calling
`optimizer.step()`, updating a parameter or saving a new model checkpoint is outside
the frozen protocol.

## Frozen inference and evaluation

```bash
python -u tools/audit_s2hr_fida.py \
  --val-root /home/duyanhong/reseg-data/raw/BCSS-WSSS/val \
  --a0-checkpoint /home/duyanhong/sshr-official-25ep-final-retry2-20260815/runs/bcss_seed42/checkpoints/stage1_last.pth \
  --s2hr-checkpoint /home/duyanhong/experiments/S2HR_V1_FULL_25EP_SEED42_5740a43_retry2/checkpoints/epoch25_final.pth \
  --output-dir /home/duyanhong/experiments/S2HR_V1_FIDA_<audit_commit> \
  --num-workers 4 \
  --parity-images 32
```

The command first compares the audit Full variant against released S²HR inference
on exactly 32 images. It proceeds only when max CAM difference, final differing
pixels and mIoU delta are all exactly zero.

For every full-validation image, V00/V10/V01/V11 and the preregistered positive
sign diagnostic reuse exactly the same three TTA backbone feature sets and one
official predicted-presence mask.

## Metric definitions

- Final segmentation: official 3-way TTA, thresholds `[0.8, 0.9, 0.8, 0.6]`,
  per-class min-max, `0/0.6/0.2/0.2` fusion and released `iouutils.scores()`.
- HMA regions: foreground tissue transitions with B0 `<=2 px`, B1 `3–7 px`,
  and B2 `>=8 px`.
- BPS boundary primary target: transitions only among C0–C3, nearest-neighbour
  28×28 mapping and a fixed one-feature-pixel transition band. Boundary quality
  pools the three actual controller maps after unflipping them at native 28×28.
- Teacher reliability: GT masks and image presence are diagnostic targets only;
  they never enter model forward or final deployed prediction. Deep and raw28_1
  diagnostic logits are TTA-averaged before applying GT/deployed presence.

## Stop boundary

After the report, stop. Fresh BPS-only/SPSR training, redesigned coupling, gamma
constraints, teacher changes, boundary-width changes, other seeds, LUAD and test
all require a separate reviewed protocol.
